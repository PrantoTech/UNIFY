# AI DETECTION PROMPTS - Quick Reference Guide

## Purpose
These prompts are used to detect AI-generated content in student submissions. They can be used with ChatGPT, Claude, or any LLM for manual verification, or integrated into automated detection systems.

---

## 🤖 Prompt 1: Code Analysis for AI Detection

### Use Case:
Analyze student code submissions to detect if they were generated by AI tools like ChatGPT, GitHub Copilot, or other code generation tools.

### Prompt:
```
You are an expert code reviewer tasked with detecting AI-generated code. 
Analyze the following code submission carefully.

CODE SUBMISSION:
```
[PASTE STUDENT CODE HERE]
```

Please analyze this code for the following AI generation indicators:

1. **Formatting & Style:**
   - Is the formatting overly perfect and consistent?
   - Are there unusual indentation or spacing patterns?
   - Does it follow a very generic, textbook-like style?

2. **Comments:**
   - Are comments excessively detailed or generic?
   - Do comments use unnatural language patterns?
   - Are there AI-typical comment phrases like "This function does...", "Note:", "TODO: Implement"?

3. **Variable Naming:**
   - Are variable names too generic (result, data, temp, item, value)?
   - Is naming too consistent across the codebase?
   - Lack of personal naming style?

4. **Code Structure:**
   - Is error handling overly perfect for a student?
   - Are there unnecessary try-catch blocks everywhere?
   - Perfect separation of concerns?

5. **Documentation:**
   - Every function documented with perfect docstrings?
   - Docstrings follow exact format (Args, Returns, Raises)?
   - Usage examples in every docstring?

6. **Patterns:**
   - Presence of "if __name__ == '__main__':" in simple scripts
   - "Import necessary libraries" comments
   - Type hints everywhere (unusual for students)

7. **Student Level:**
   - Does code complexity match expected student level?
   - Are advanced concepts used without basic understanding?

**Provide:**
1. AI Confidence Score (0-100): How confident are you this is AI-generated?
2. Specific Indicators: List all AI patterns found
3. Evidence: Quote specific code snippets that indicate AI generation
4. Verdict: HUMAN-WRITTEN, SUSPICIOUS, or AI-GENERATED
5. Recommendation: Should this submission be flagged?
```

## 📝 Prompt 2: Text/Essay Analysis for AI Detection

### Use Case:
Analyze written assignments, project descriptions, reports, or documentation to detect AI-generated text.

### Prompt:
```
You are an expert at detecting AI-generated text. Analyze the following student submission carefully.

TEXT SUBMISSION:
"""
[PASTE STUDENT TEXT HERE]
"""

Please analyze this text for the following AI generation indicators:

1. **Language & Tone:**
   - Is the language overly formal or professional for a student?
   - Perfect grammar with no minor errors?
   - Lack of personal voice or individual style?
   - Absence of colloquialisms or casual language?

2. **Structure & Flow:**
   - Are paragraphs unnaturally balanced in length?
   - Repetitive sentence structures?
   - Perfect transitions between ideas?
   - Over-use of transitional phrases?

3. **AI-Typical Phrases:**
   - "In conclusion," to start conclusions
   - "Furthermore," "Moreover," "Nevertheless"
   - "It is important to note that"
   - "In today's world/society/era"
   - "plays a crucial role in"
   - "Let's dive in/into"
   - "Here's what you need to know"

4. **Content Quality:**
   - Too comprehensive for student level?
   - Generic, textbook-like content?
   - Lacks specific examples or personal insights?
   - Perfect organization and structure?

5. **Errors & Authenticity:**
   - Complete absence of typos or minor errors?
   - No double spaces or formatting mistakes?
   - Too polished for a student submission?

6. **Vocabulary:**
   - Overly diverse vocabulary?
   - Uncommon words used correctly?
   - Academic jargon without student context?

**Provide:**
1. AI Confidence Score (0-100): How confident are you this is AI-generated?
2. Specific Indicators: List all AI patterns found
3. Evidence: Quote specific sentences that indicate AI generation
4. Writing Level Assessment: Does this match expected student writing?
5. Verdict: HUMAN-WRITTEN, SUSPICIOUS, or AI-GENERATED
6. Recommendation: Should this submission be flagged?
```

## 🔍 Prompt 3: Plagiarism & Similarity Detection

### Use Case:
Compare two submissions to detect copying, AI-generated duplicates, or plagiarism.

### Prompt:
```
You are an expert at detecting plagiarism and AI-generated content similarities.
Compare the following two submissions carefully.

SUBMISSION 1 (Student A):
"""
[PASTE FIRST SUBMISSION]
"""

SUBMISSION 2 (Student B):
"""
[PASTE SECOND SUBMISSION]
"""

Please analyze and compare these submissions:

1. **Similarity Analysis:**
   - What is the percentage of similarity between these two submissions?
   - Are there identical or near-identical sections?
   - Do they share unusual phrases or patterns?

2. **Source Determination:**
   - Is this human-to-human copying?
   - Could both be generated by the same AI tool?
   - Is one AI-generated and one copied from it?
   - Are they independently written with coincidental similarities?

3. **Pattern Matching:**
   - Do they share the same structure?
   - Same variable names or function signatures?
   - Similar comments or documentation?
   - Identical error handling patterns?

4. **Evidence:**
   - Provide specific examples of matching content
   - Highlight suspicious similarities
   - Note any unique identifiers

**Provide:**
1. Similarity Score (0-100%): How similar are these submissions?
2. Plagiarism Type: IDENTICAL, PARAPHRASED, AI-DUPLICATE, or INDEPENDENT
3. Evidence: Quote matching sections
4. AI Involvement: Could AI be involved in either or both?
5. Verdict: Are these submissions too similar to be coincidental?
6. Recommendation: Should these be flagged for review?
```

## 🎯 Prompt 4: Project Progress Authenticity Check

### Use Case:
Verify if project progress is genuine or artificially created (e.g., mass commits, fake milestones).

### Prompt:
```
You are reviewing a student's project progress for authenticity.

PROJECT INFORMATION:
- Project Start Date: [DATE]
- Current Date: [DATE]
- Student Level: [YEAR/SEMESTER]
- Project Type: [DESCRIPTION]

PROGRESS DATA:
```
Total Commits: [NUMBER]
Commit Timeline: [LIST OF DATES]
Code Changes: [SUMMARY]
Milestones Claimed: [LIST]
```

SAMPLE COMMITS:
"""
[PASTE COMMIT MESSAGES AND SAMPLES]
"""

Please analyze this project progress:

1. **Timeline Analysis:**
   - Is the commit timeline realistic?
   - Are there suspicious patterns (all commits on one day, mass midnight commits)?
   - Does progress align with typical student work patterns?

2. **Commit Quality:**
   - Are commit messages generic or specific?
   - Do commits show incremental progress?
   - Are there "all-in-one" commits that add entire features?

3. **Code Evolution:**
   - Does code show learning/iteration?
   - Are there mistakes followed by fixes?
   - Is everything perfect from the start?

4. **Red Flags:**
   - Repository created recently but claims long history?
   - Mass commits in short timeframe?
   - No commit activity for weeks then sudden burst?
   - All commits at unusual hours (2-5 AM)?

**Provide:**
1. Authenticity Score (0-100): How authentic is this progress?
2. Suspicious Patterns: List all red flags found
3. Evidence: Specific examples of concerning behavior
4. Verdict: AUTHENTIC, SUSPICIOUS, or FABRICATED
5. Recommendation: Further investigation needed?
```

## 💡 Prompt 5: Live Coding Interview Assessment

### Use Case:
When a student is flagged, this prompt helps assess a live coding demonstration to verify authenticity.

### Prompt:
```
You are observing a live coding session to verify a student's capabilities.

STUDENT'S SUBMITTED PROJECT:
[DESCRIPTION OF ORIGINAL SUBMISSION]

LIVE CODING TASK GIVEN:
[DESCRIPTION OF TASK - should be similar to project scope]

STUDENT'S LIVE PERFORMANCE:
- Time Taken: [MINUTES]
- Code Quality: [DESCRIPTION]
- Errors Made: [LIST]
- Problem-Solving Approach: [DESCRIPTION]

LIVE CODE PRODUCED:
```
[PASTE CODE FROM LIVE SESSION]
```

COMPARISON METRICS:
- Original Project Code Quality: [SCORE]
- Live Session Code Quality: [SCORE]
- Complexity Match: [YES/NO]
- Style Similarity: [PERCENTAGE]

Please analyze:

1. **Capability Match:**
   - Can the student produce similar quality code live?
   - Do they understand concepts used in their project?
   - Is their problem-solving approach consistent?

2. **Quality Comparison:**
   - How does live code compare to submitted project?
   - Significant quality drop in live session?
   - Different coding style or patterns?

3. **Knowledge Assessment:**
   - Does student understand their own code?
   - Can they explain design decisions?
   - Struggle with concepts they "used" in project?

4. **Red Flags:**
   - Unable to reproduce similar work?
   - Can't explain their own project code?
   - Completely different skill level?
   - No understanding of "their" implementation?

**Provide:**
1. Skill Match Score (0-100): Does live performance match project?
2. Verdict: AUTHENTIC (student did the work), SUSPICIOUS, or FRAUD (clearly didn't do the work)
3. Evidence: Specific discrepancies or confirmations
4. Recommendation: Final decision on academic integrity case
```

## 📊 Prompt 6: Batch Analysis for Class-Wide Detection

### Use Case:
Analyze multiple submissions from a class to identify patterns of AI use or cheating.

### Prompt:
```
You are analyzing submissions from an entire class to detect patterns of AI use or plagiarism.

CLASS INFORMATION:
- Number of Students: [NUMBER]
- Assignment Type: [DESCRIPTION]
- Submission Deadline: [DATE]

SUBMISSIONS SUMMARY:
[For each student, provide: Student ID, Submission Length, Quality Score, Timestamp]

SAMPLE SUBMISSIONS (Top 5 suspected):
1. Student [ID]:
"""
[SUBMISSION]
"""

2. Student [ID]:
"""
[SUBMISSION]
"""

[Continue for all suspects...]

Please analyze:

1. **Pattern Detection:**
   - Do multiple submissions share AI characteristics?
   - Are there clusters of similar submissions?
   - Unusual timing patterns (all submitted at exact same time)?

2. **Quality Anomalies:**
   - Submissions significantly above typical class level?
   - Unusually uniform quality across students?
   - Some students showing sudden quality jumps?

3. **Similarity Clusters:**
   - Groups of students with nearly identical work?
   - Same AI tool used by multiple students?
   - Copy-paste between students?

4. **Statistical Outliers:**
   - Which submissions are statistical anomalies?
   - Who shows most AI indicators?
   - Any coordinated cheating?

**Provide:**
1. Class-Wide AI Use Estimate: What % likely used AI?
2. High-Risk Students: List IDs of top suspects
3. Similarity Clusters: Groups of related submissions
4. Evidence Summary: Overall patterns detected
5. Recommendations: Which students need individual review?
```

## 🚀 How to Use These Prompts

### For Manual Review:
1. Copy the appropriate prompt
2. Fill in bracketed placeholders with actual data
3. Paste into ChatGPT, Claude, or your preferred LLM
4. Review the analysis
5. Document findings in student record

### For Automated Integration:
1. Use these prompts as templates in your AI detection system
2. Programmatically fill placeholders with submission data
3. Send to OpenAI API, Claude API, or similar
4. Parse response for confidence scores and verdicts
5. Auto-flag submissions above threshold

### For Appeal Process:
1. Use prompts to get second opinion on flagged submissions
2. Document both automated and manual review results
3. Present evidence to academic integrity committee
4. Allow student to respond with live demonstration

## 📈 Calibration Guide

### Confidence Score Interpretation:

**0-30%**: Almost certainly human-written
- Minor or no AI indicators
- Natural style and errors present
- Action: Clear, no review needed

**31-50%**: Likely human with possible AI assistance
- Some AI patterns but not conclusive
- Could be legitimate use of tools or tutoring
- Action: Note in record, monitor future submissions

**51-70%**: Suspicious, probable AI use
- Multiple strong AI indicators
- Inconsistent with student's typical work
- Action: Flag for manual review, request clarification

**71-90%**: High confidence AI-generated
- Numerous AI signatures present
- Clear mismatch with student capability
- Action: Formal review process, interview required

**91-100%**: Extremely high confidence, almost certainly AI
- Overwhelming AI evidence
- Textbook AI patterns throughout
- Action: Academic integrity violation process

## 🔧 Customization Tips

### Adjust for Different Contexts:

**For Introductory Courses:**
- Lower thresholds (AI help more obvious in beginners)
- Focus on understanding gaps
- More emphasis on live demonstration

**For Advanced Courses:**
- Higher sophistication expected
- Focus on innovation and originality
- Compare against student's academic history

**For Different Programming Languages:**
- Adjust typical patterns per language
- Consider language-specific AI behaviors
- Account for framework conventions

**For Different Assignment Types:**
- Essays vs Code vs Math
- Individual vs Group work
- Open-book vs Closed-book
- Timed vs Untimed
